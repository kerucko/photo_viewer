# Архитектура и решения

## Слои

`PhotoCore` — независимые от UI структуры `PhotoResource`, `PhotoAsset`, `CatalogEntry`,
каталог `FolderCatalog: CatalogSource`, сортировка, `SelectionState` с ревизией запросов.
URL используется для выделения в текущем каталоге; происхождение библиотечных ресурсов
и состояние удаления отдельно хранятся в манифесте.

`BrowserModel` — состояние главного окна на MainActor: история папок, выделение,
вид, сортировка и запрос предпросмотра. Сканирование идёт в отдельной задаче.
Ревизия папки и ревизия выделения защищают от запоздавших результатов.

`ImageService` — ImageIO для JPEG/миниатюр, CIRAWFilter для полноразмерного RAF.
Очередь ограничена двумя декодированиями. Отменённые ожидающие запросы пропускают
декодирование; уже начатая операция Core Image завершается, но результат отбрасывается.
NSCache имеет бюджет 512 МиБ декодированных изображений (это не лимит памяти всего процесса).
Ключ: путь, размер файла, дата изменения, размер рендера. Предзагрузка соседних JPEG;
полный RAF загружается при выборе одиночного RAF или переключении пары на RAW. Миниатюры запрашиваются видимыми элементами.

SwiftUI управляет окном, панелями и композицией. NSCollectionView реализует сетку,
NSTableView — таблицу; списки колонок компонованы SwiftUI. AppKit CanvasView рисует
CGImage и управляет жестами; отрисовка ограничена bounds и границей PreviewPane.
Корневой hosting view ячейки сетки сохраняется при обновлении; его размер задаёт layout. ViewportState вынесен отдельно для будущего общего viewport.
ImageIO применяет ориентацию при декодировании. Core Image выдаёт цветоуправляемый
sRGB-рендер RAW; JPEG сохраняет цветовое пространство декодера.

## Видимость выделения

Выделение остаётся в модели; прокруткой управляет UI. `SelectionScrollRequest`
содержит расположение, режим, выбранный ID и порядок ID каталога. Одинаковый запрос
не повторяется при обновлении предпросмотра или миниатюр. Смена расположения,
выделения или порядка записей обновляет запрос.

Сетка и таблица используют `SelectionScrollView`: одноразовый запрос выполняется
после присоединения к окну и раскладки содержимого с ненулевым размером. Перед
прокруткой сверяется актуальность запроса; устаревший запрос отбрасывается. Сетка
показывает прямоугольник ячейки, таблица вызывает `scrollRowToVisible`.
Текущая колонка имеет отдельный вертикальный `ScrollViewReader` со стабильными ID
строк. Горизонтальный reader следит через `onScrollGeometryChange` за шириной
содержимого и области просмотра и после получения геометрии показывает
`current-folder` с якорем `.trailing`. При смене папки reader пересоздаётся через
`.id(model.folder)`. Смещение прокрутки исключено из наблюдаемой геометрии, поэтому
ручная горизонтальная прокрутка не запускает возврат к правому краю.
Колонки и галерея используют
начальную реакцию на запрос; галерея центрирует выбранную миниатюру.
При смене `filmstripSize` пересоздаётся только reader ленты, чтобы прокрутка учитывала
новую геометрию. `PreviewPane` и его Canvas сохраняются. Произвольных задержек и
анимации нет; публичные API, формат хранения и декодирование не меняются.

## Границы будущих функций

- Управляемая библиотека уже хранит происхождение, контрольные суммы и состояние удаления.
  Устойчивая идентификация источника между разными точками монтирования остаётся будущей задачей.
- Инструкции редактирования должны храниться отдельно от файлов и применяться в сервисе рендера.
- Экспорт получает ресурс/снимок и инструкции рендера, не зависит от конкретного представления.
- Будущая синхронизация не должна считать недоступный носитель или отсутствующий файл командой удаления.

## Сборка

Swift Package Manager без внешних зависимостей. Минимальная система macOS 26.
Скрипт формирует bundle и локальную ad-hoc подпись. Кеши сборки лежат в `.build`.
Исходник значка хранится в `Resources/AppIcon.png`. `scripts/build-app.sh` через
`sips` создаёт в `.build/AppIcon.iconset` десять вариантов 16–1024 пикселей,
через `iconutil` упаковывает их в `Contents/Resources/AppIcon.icns` и задаёт
`CFBundleIconFile` в `Info.plist` до подписи bundle.
Настройка глобального окружения, установка Xcode и notarization не требуются.

## Метаданные и настройки просмотра

`PhotoMetadata` в PhotoCore читает свойства через ImageIO без декодирования пикселей,
возвращает Sendable-секции и поля. `MetadataSidebar` читает их в фоновой задаче только
для текущего файла; отменённая задача не публикует устаревший результат. При ошибке
контейнера сохраняется доступ к файловым атрибутам и выводится предупреждение.
Настройки `filmstripSize` и `showMetadata` хранятся в UserDefaults, состояние масштаба
общее для кнопок и команд меню. Инспектор встроен через SwiftUI inspector.

## Управляемая библиотека и Корзина

`PhotoLibrary` — actor, сериализующий операции с `library.json` и копиями в `Originals`.
Подкаталоги по хешу источника сохраняют исходную структуру; UI получает плоский снимок
каталога с группировкой пар внутри исходных папок. `LibrarySnapshot` возвращает записи
и предупреждения отдельно: отсутствие одного файла не закрывает всю библиотеку.

Импорт рекурсивно копирует поддерживаемые обычные файлы, исключая символьные ссылки,
проверяет SHA256, даты и xattrs. Существующие оригиналы не перезаписываются. Манифест
хранит путь/UUID тома источника, относительный путь, хеш и состояния удаления.
Повторы пропускаются, изменения сообщаются как конфликты. Записи удаления предотвращают
автоматическое восстановление копий при повторном импорте. Осиротевшая копия после
прерывания принимается только после проверки соответствия источнику; конфликтующая
не перезаписывается. Полная устойчивость ко всем сбоям питания ещё не проверена.

`PhotoTrash` использует системный `FileManager.trashItem`, возвращая перемещённые файлы
и ошибки отдельно. Библиотечное удаление согласуется с журналом; удаление в обычной
папке действует непосредственно на её файлы. `BrowserModel` хранит тип текущего
расположения, сохранённый корень библиотеки и блокирует конфликтующие действия во время
импорта/удаления. UI подтверждает весь набор ресурсов пары до операции.
